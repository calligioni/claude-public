# Internationalization & multi-locale mirroring

Many production sites ship multiple language mirrors — `/fr/`, `/de/`, `/es/`, `/jp/`. The skill's defaults assume the WPML pattern (slug translation in path), but real targets use varied strategies.

## Detect the strategy

Before porting any FR pages, detect HOW the original organizes locales:

```bash
TARGET="https://<target>"
HOME_HTML="$work/html/<homepage>"

echo "=== hreflang declarations ==="
grep -oE '<link[^>]*rel="alternate"[^>]*hreflang="[^"]+"[^>]*href="[^"]+"' "$HOME_HTML"

echo
echo "=== <html lang> ==="
grep -oE '<html[^>]*lang="[^"]+"' "$HOME_HTML"

echo
echo "=== Common i18n widgets ==="
grep -oE 'wpml-ls|next-intl|next-i18next|astro-i18n|svelte-i18n|vue-i18n|globalize' "$HOME_HTML" | sort -u
```

## Common strategies

| Pattern | Example | Notes |
|---|---|---|
| **Path prefix** | `/fr/about/`, `/de/about/` | Most common. Astro handles natively. |
| **Slug translation** | `/fr/agence/`, `/de/agentur/` | WPML / many WP plugins. Each locale has different slugs. |
| **Subdomain** | `fr.example.com`, `de.example.com` | Requires DNS, usually NOT done in a local replica. |
| **Query parameter** | `?lang=fr` | Rare for SEO reasons. Some Webflow / Wix sites. |
| **TLD per locale** | `example.fr`, `example.de` | Multi-deployment. Replicate one or all? Ask user. |

## The slug-translation pattern (WPML / similar)

WPML's `wpml-ls-legacy-list-horizontal` widget renders the language switcher. The captured HTML has a hidden `<div class="site-language">` with `wpml-ls-*` classes that the original WPML JS reads to populate the visible `.lang-ls` span.

Your port replaces the WPML JS with an inline script that reads the current `<html lang>` and writes the OTHER locale's 2-letter code into every `.lang-ls`:

```html
<script is:inline>
  (function () {
    function fill() {
      var html = document.documentElement.lang || "en";
      var isFr = /^fr/i.test(html);
      var other = isFr ? "EN" : "FR";
      document.querySelectorAll(".lang-ls").forEach(function (s) {
        if (!s.textContent.trim()) s.textContent = other;
      });
      document.querySelectorAll("a.lang-switcher").forEach(function (a) {
        if (!a.getAttribute("href") || a.getAttribute("href") === "#!") {
          a.setAttribute("href", isFr ? "/" : "/fr/");
        }
      });
    }
    if (document.readyState === "loading") document.addEventListener("DOMContentLoaded", fill);
    else fill();
  })();
</script>
```

For 3+ locales, store the mapping in a JSON object:

```ts
const LOCALE_MAP = {
  "en-US": { other: ["FR", "DE"], href: ["/fr/", "/de/"] },
  "fr-CA": { other: ["EN", "DE"], href: ["/", "/de/"] },
  "de-DE": { other: ["EN", "FR"], href: ["/", "/fr/"] },
} as const;
```

## Slug translation table

When FR / DE / ES routes use different slugs than EN, you need a translation table per page:

```ts
// src/lib/i18n/routes.ts
export const ROUTES: Record<string, Record<"en" | "fr" | "de", string>> = {
  about:    { en: "/about/",    fr: "/fr/a-propos/",    de: "/de/uber-uns/" },
  work:     { en: "/work/",     fr: "/fr/travaux/",     de: "/de/arbeiten/" },
  services: { en: "/services/", fr: "/fr/services/",    de: "/de/leistungen/" },
  contact:  { en: "/contact/",  fr: "/fr/contact/",     de: "/de/kontakt/" },
};

export function localizePath(canonical: string, locale: "en" | "fr" | "de"): string {
  const route = ROUTES[canonical];
  return route ? route[locale] : canonical;
}
```

Then Header/Footer take the current locale and call `localizePath("services", lang)` for each nav item.

## hreflang preservation

Production sites declare `hreflang` for SEO. Preserve verbatim:

```astro
<link rel="alternate" hreflang="en" href={`https://${site}${enPath}`} />
<link rel="alternate" hreflang="fr" href={`https://${site}${frPath}`} />
<link rel="alternate" hreflang="x-default" href={`https://${site}${enPath}`} />
```

Auto-generate per page from the slug translation table.

## RTL languages (Arabic, Hebrew, Farsi, Urdu)

If any locale is RTL, the page direction flips. Add to BaseLayout:

```astro
const dir = ["ar", "he", "fa", "ur"].some(prefix => lang.startsWith(prefix)) ? "rtl" : "ltr";
---
<html lang={htmlLang} dir={dir}>
```

CSS-wise, prefer logical properties (`margin-inline-start`, `padding-inline-end`) over `margin-left` / `padding-right` so layouts mirror naturally.

## Per-locale content

Page bodies are translated. Either:

1. **Inline per locale** — `src/pages/fr/contact.astro` and `src/pages/contact.astro` have hand-translated content. Simpler, no runtime overhead, but duplicate effort if content changes.
2. **Content collection with `lang` field** — single source, `getStaticPaths` generates per-locale routes. More work upfront, easier to maintain.

For a faithful replica of an existing site, option 1 is usually correct — the captured HTML already has per-locale content.

## Currency, dates, numbers

If the original shows prices ("$X CAD" vs "X € HT"), preserve verbatim from the captured HTML. Don't introduce `Intl.NumberFormat` formatting — it'll diverge from the original's exact rendering.

## Date strings on blog posts

```ts
// Per-locale date formatter
const fmt = new Intl.DateTimeFormat(
  lang === "fr" ? "fr-CA" : "en-US",
  { year: "numeric", month: "long", day: "numeric" }
);
fmt.format(new Date(post.date));
```

Match the original's exact wording — "May 18, 2026" (EN), "18 mai 2026" (FR), etc.

## Search & sitemap per locale

When generating the sitemap, emit one entry per locale:

```js
// astro.config.mjs
import sitemap from "@astrojs/sitemap";

export default {
  integrations: [
    sitemap({
      i18n: {
        defaultLocale: "en",
        locales: { en: "en-US", fr: "fr-CA" },
      },
    }),
  ],
};
```

## Anti-patterns

- Don't auto-machine-translate content. The original's copy was human-written; replicate it.
- Don't drop hreflang during port — Google ranks multi-locale sites by hreflang presence.
- Don't mix locales on a single page (English nav over French body).
- Don't assume FR is the only secondary locale. Many sites ship 4-8.
- Don't translate slugs that the production site keeps in English (some sites use English slugs across all locales for SEO; preserve their decision).
